Enterprise Knowledge Assistant (Local-First Edition)This project is a complete, self-hosted, and production-ready RAG (Retrieval-Augmented Generation) assistant. It is designed to answer questions using only your internal Confluence documentation, ensuring zero-hallucination and 100% source attribution.This "Local-First" edition is built to run entirely on your local machine using Docker Compose, with a local LLM server (llama-cpp-python) for full data privacy.FeaturesZero Hallucination: The LLM is restricted to answering only from the context provided by your documentation. If no context is found, it will say so.Source Attribution: Every answer is backed by clickable links to the exact Confluence pages (with version) used to generate the response.100% Local & Private: Runs entirely in Docker. Your documents and questions never leave your machine.Enterprise-Grade Data Pipeline:Syncs with your Confluence spaces [cite: src/data_pipeline.py].Cleans and token-aware chunks (300-500 tokens) [cite: src/data_pipeline.py].Handles document versions to keep data fresh [cite: src/data_pipeline.py].Two-Model System:Embedding Model (all-mpnet-base-v2): The "Librarian" that indexes and finds relevant information.Language Model (Mistral-7B-Instruct): The "Brain" that reads context and writes the answer.ArchitectureThe system runs as a set of coordinated services, all managed by docker-compose.yml.See ARCHITECTURE.md for a detailed diagram and data flow.Prerequisites (MANDATORY)Before you begin, you must complete these steps:Install Docker: You must have Docker Desktop (or Docker Engine + Compose) installed and running.Download the LLM Model:Create a new folder in this project directory named models.Go to: https://huggingface.co/TheBloke/Mistral-7B-Instruct-v0.2-GGUFDownload the file: mistral-7b-instruct-v0.2.Q4_K_M.gguf (~4.37 GB).Place this downloaded .gguf file inside the models folder.Get Confluence Credentials:Your Confluence site URL (e.g., https://your-company.atlassian.net/wiki).Your Atlassian account email (CONFLUENCE_USERNAME).A Confluence API Token (CONFLUENCE_API_TOKEN). Get one here.How to Run (5-Minute Setup)Clone the Repository:git clone <your-repo-url>
cd enterprise-rag-local
Create Your Environment File:Copy the example file.cp .env.example .env
Edit Your Environment File (.env):Open the .env file and fill in your Confluence details.# --- REQUIRED ---
CONFLUENCE_BASE_URL=[https://your-company.atlassian.net/wiki](https://your-company.atlassian.net/wiki)
CONFLUENCE_API_TOKEN=YourAPITokenHere
CONFLUENCE_USERNAME=your-email@company.com
CONFLUENCE_SPACES=ENG,HR # (The Confluence "Space Keys" you want to sync)

# --- OPTIONAL ---
# (No changes needed unless you change the model file name)
LLM_MODEL_FILE=mistral-7b-instruct-v0.2.Q4_K_M.gguf
Build and Run All Services:This single command will build all the containers, start the services, and run the data ingestion.docker-compose up -d --build
What's happening?The ingest service will start, initialize the database (init_db), and then begin fetching, chunking, and embedding all your Confluence pages.You can watch its progress: docker-compose logs -f ingestThis one-time setup may take several minutes depending on the size of your Confluence spaces.Start Asking Questions!Once the ingest service logs show "Full Confluence sync completed", your assistant is ready.Open your browser and go to: http://localhost:8501Service OverviewThis docker-compose.yml runs 5 services:qdrant: The vector database that stores your document embeddings.llama-cpp: The local LLM server. It loads the Mistral-7B model file from your models folder and serves it at http://llama-cpp:8080.api: The FastAPI "brain" that receives user queries, fetches context from qdrant, and gets an answer from llama-cpp. Runs at http://localhost:8000.ui: The Streamlit web interface you interact with. Runs at http://localhost:8501.ingest: A one-time job that runs init_db.py and data_pipeline.py to populate your database. It will show "Exit 0" when finished.How to Re-Sync DataIf your Confluence documents change, you can manually re-run the ingestion:docker-compose run --rm ingest
This will run the run_ingestion.py script again, which intelligently updates only the pages that have changed.
